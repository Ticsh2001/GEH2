# Internal Expression Syntax (CodeGen Output)

This document describes the expression language generated by the built-in code generator and stored in project files. It is evaluated by the visualizer and later transformed for the target system.

## General Rules

- Expressions consist of **signal names**, **numeric constants**, **operators**, and **function calls**.
- Signal names may contain letters, digits, underscores, and the special character `§`.
- Signal names starting with a digit are written directly, **without** the `P` prefix (the prefix is added only in the final system-specific export).
- Spaces are allowed around operators and after commas.
- String literals for table names or signal references inside certain functions must be enclosed in single quotes `'...'` or double quotes `"..."`.
- The `§` character is part of the signal name and is **not** replaced inside the internal code.

## Operators

| Operator | Meaning | Example |
|----------|---------|----------|
| `+` `-` `*` `/` | Arithmetic | `A + B * 2` |
| `>` `<` `>=` `<=` `=` `!=` | Comparison | `A > 100` |
| `AND` `OR` `NOT` | Logical (AND, OR, NOT) | `(A > 0) AND (B < 10)` |

- Note: The internal code uses the keywords `AND`, `OR`, `NOT` instead of `&&`, `||`, `!`. Conversion happens later.
- Comparison for equality is a single `=` (not `==`).

## Numeric Constants

- Written as integer or decimal numbers, e.g., `0`, `-1`, `3.14`, `1.5e-3`.
- Unary minus before a signal (e.g., `-KKS_TAG`) is allowed in the internal code and will be handled during final export.

## Conditional Expression

```
WHEN(condition, value_if_true, value_if_false)
```
- Returns `value_if_true` if `condition` is true (non-zero), otherwise `value_if_false`.
- All arguments are evaluated element-wise over the time series.

## Math Functions

| Function | Description |
|----------|-------------|
| `ABS(x)` | Absolute value |
| `EXP(x)` | Exponential e^x |
| `POW(x, y)` | Power x^y |
| `LOG(x)` | Natural logarithm (x > 0) |
| `LOG10(x)` | Base-10 logarithm (x > 0) |
| `MIN(a, b, ...)` | Minimum of arguments |
| `MAX(a, b, ...)` | Maximum of arguments |
| `AVG(a, b, ...)` | Average of arguments |
| `MED(a, b, ...)` | Median of arguments |
| `ROUND(x, n)` | Round x to n decimal places (n defaults to 0) |

## History / Rolling Functions

These functions operate on the past values of a signal within a specified time window (in minutes).

| Function | Description |
|----------|-------------|
| `HISTORYAVG(signal, period)` | Arithmetic mean over the window |
| `HISTORYSUM(signal, period)` | Sum over the window |
| `HISTORYCOUNT(signal, period)` | Count of non-NaN values in the window |
| `HISTORYMAX(signal, period)` | Maximum value in the window |
| `HISTORYMIN(signal, period)` | Minimum value in the window |
| `HISTORYDIFF(signal, period)` | Difference between max and min in the window |
| `HISTORYGRADIENT(signal, period)` | Slope of linear regression over the window (value per minute) |

- `signal`: a signal name. **Important:** the signal argument must be enclosed in quotes (single or double), regardless of whether it starts with a digit or a letter. Example: `HISTORYAVG('10MAA01', 60)`.
- `period`: integer number of minutes (e.g., `60` for one hour).

## Previous Value

```
PREV(signal)
```
- Returns the previous value of the signal (one time step before).
- Same quoting rules as for `HISTORY*` functions: `PREV('10MAA01')`.

## Table Interpolation Functions

### 1D Interpolation

```
GETPOINT("table_name", X_value, Y_value, axis_to_find)
```
- Finds `Y` given `X` (or vice versa) by linear interpolation from a 2‑column table.
- `table_name`: string literal identifying the table.
- `axis_to_find`: `"Y"` to get Y for a given X, or `"X"` to get X for a given Y.

### Multi‑dimensional Interpolation

```
INTERPOLATE("table_name", "target_column", value1, value2, ...)
```
- Performs KNN‑based interpolation using a table with multiple feature columns.
- `table_name`: string literal.
- `target_column`: name of the column whose value is being interpolated.
- `value1, value2, ...`: input values for each feature column (order must match the table columns except the target column).

## Notes for LLM

- This is the **internal representation**, not the final system code. Some transformations (like adding `P` prefix, converting `AND` to `&&`, replacing `§` with `_`) are applied later by a post‑processing step.
- When describing a parameter or rule, refer to signals by their KKS names as they appear in the expression (including `§` where present).
- If the `code` field is truncated (`code_truncated: true`), the full expression is too long to fit; use the provided portion for context.
